# Архив протоколов (MVP, этап 3)

Локальный архив протоколов об административных правонарушениях. Работает без облачных
сервисов и без ИИ-моделей. **Оригиналы документов не копируются и не изменяются** — они
только читаются (для вычисления хэша и размера). В базе SQLite хранятся извлечённые
сведения и пути к оригиналам.

## Что реализовано

| Возможность | Состояние |
|---|---|
| Схема SQLite, миграции (сейчас версия 2), репозиторий, поиск | готово (этап 1) |
| Резервное копирование базы с проверкой целостности и ротацией | готово (этап 1) |
| Главное окно на русском, ручной ввод протоколов | готово (этап 1) |
| Текст из PDF с текстовым слоем (PyMuPDF) | готово (этап 2) |
| OCR сканов PDF (Tesseract, язык `rus`) | готово (этап 2) |
| Текст из DOCX и ODT (python-docx, odfpy), включая таблицы | готово (этап 2) |
| Текст из DOC (конвертация LibreOffice → DOCX) | готово (этап 2) |
| Обработка в фоновом потоке с прогрессом и отменой, статусы и причины ошибок | готово (этап 2) |
| Поиск документов и протоколов по извлечённому тексту | готово (этап 2) |
| Извлечение реквизитов правилами и регулярными выражениями: номер, дата протокола, дата и место нарушения, нарушенные пункты ГОСТ, статья, тип и наименование лица, орган/составитель — для формы «в отношении юридического лица» | готово (этап 3), проверено на одном образце |
| ИНН, ОГРН, адрес лица | **не извлекаются** (в базе нет таких полей) |
| Восстановление базы из копии | **не реализовано** (копию можно подставить вручную, см. ниже) |


## Обработка документов (этап 2)

1. «Файл → Добавить документы…» — документ регистрируется по пути (статус «Добавлен, не
   обработан»). Файл только читается.
2. Вкладка «Документы»: «Обработать выбранный» или «Обработать все новые и с ошибками».
   Обработка идёт в фоновом потоке; окно показывает прогресс, есть кнопка «Отмена»
   (необработанные документы остаются в очереди).
3. Успех — статус «Обработан», текст сохранён в базе. Неудача — статус «Ошибка обработки» и
   причина в колонке «Сообщение» (повреждённый или защищённый паролем файл, нет OCR или
   LibreOffice, пустой документ и т. п.). Тихо подставленного или пустого результата нет.
4. «Показать текст» (или двойной щелчок) открывает извлечённый текст; страницы PDF разделены.
5. Поле «Найти документы по тексту или имени файла» ищет по извлечённому тексту (все слова,
   без учёта регистра, по началу слова) и по имени файла.

Как читается каждый формат:

* **PDF** — текстовый слой постранично. Страница почти без текста, но с изображением,
  считается сканом и распознаётся Tesseract (300 dpi). То же при испорченном текстовом слое
  (много символов �). Пустая страница без изображений пропускается. Если нужен OCR, а
  Tesseract или язык `rus` не установлены, документ получает статус «Ошибка» с пояснением,
  а не частичный текст.
* **DOCX, ODT** — абзацы и таблицы в порядке следования (ячейки таблицы через табуляцию,
  объединённые ячейки без дублей).
* **DOC** — LibreOffice без интерфейса конвертирует **временную копию** файла в DOCX во
  временной папке; затем копия и результат удаляются. Оригинал LibreOffice не открывает,
  поэтому рядом с ним не появляются файлы блокировки. В архиве и базе копия не хранится.

## Извлечение реквизитов (этап 3)

Кнопки на вкладке «Документы»: «Извлечь реквизиты» (выбранный документ) и «Извлечь реквизиты
у всех обработанных без протокола». Сначала документ должен быть обработан (получен текст).

Принципы:

* Только явные правила (регулярные выражения), без ИИ и без угадывания. Нашлось по правилу —
  поле заполнено; не нашлось — поле пустое, а причина показана в итоговом сообщении.
* Значения не «исправляются»: например, несуществующая дата в тексте не превращается в
  существующую, а поле остаётся пустым.
* Для каждого значения сохраняется **фрагмент исходного текста и имя правила**. Они видны в
  карточке протокола («Автоматически извлечено…») — так можно сверить значение с оригиналом.
* Запись получает статус «Извлечён автоматически». Статус «Проверен» ставите только вы.
* Протокол, внесённый вручную или уже «Проверен», повторное извлечение не трогает. Автоматически
  извлечённая запись при повторном запуске обновляется.

Правила (форма «Протокол … об административном правонарушении в отношении юридического лица»):

| Поле | Откуда берётся |
|---|---|
| Номер протокола | заголовок `ПРОТОКОЛ 86 НН 122990` в начале строки; приводится к виду `86 НН 122990` (слитное и строчное написание, латинские буквы серии вместо кириллических — с предупреждением) |
| Дата протокола | первая дата вида «06 февраля 2026 г.» сразу после заголовка. Дата вида `05.02.2026` из текста (например, дата осмотра) не берётся |
| Тип лица | заголовок «в отношении юридического/должностного лица» |
| Статья | только из фразы «нарушение, предусмотренное ч. 1 ст. 12.34 КоАП РФ»; упоминания других статей в тексте (права, Конституция) игнорируются |
| ФИО / наименование | строки после «в отношении:» до строки «расположенного…», «ОГРН», «ИНН» |
| Орган / составитель | блок между строкой с датой и словами «в присутствии» / «составил» (должность, звание, ФИО составителя одной строкой) |
| Дата нарушения | принимается равной **дате контрольных действий**: «…проведённых с 11 ч. 34 мин. по 16 ч. 10 мин. 05.02.2026» → 05.02.2026 (решение пользователя) |
| Место нарушения | адреса вида `ул. Мира д. 95` из блока после слова «выразившиеся»/«выразившееся» (до абзаца «По итогам…», «В соответствии…» или пустой строки; если конец блока не найден за 10 строк — поле пустое). Тип улицы приводится к виду `ул.`, `пр-кт`, `пер.`, `проезд`, `б-р`, `ш.`, `наб.`; название берётся **как записано в документе** (падеж не меняется: в тексте «по ул. Северной д. 8» → `ул. Северной д. 8`). Несколько адресов — через «; », без повторов. Места **без номера дома** (пересечения улиц) в поле не вносятся — об этом выдаётся предупреждение |
| Нарушенные пункты ГОСТ | из фраз «в нарушение п. 5.2.4 ГОСТ Р 50597-2017» и «нарушены требования …, п. 8.1, 8.8 ГОСТ Р 50597-2017, выразившиеся». Каждый пункт записывается отдельно: `п. 8.1 ГОСТ Р 50597-2017; п. 8.8 ГОСТ Р 50597-2017`. Пояснительные ссылки («в соответствии с п. 3.18 ГОСТ…», «согласно п. 8.8 ГОСТ…») нарушенными не считаются |

Что **не извлекается**: ИНН, ОГРН и адрес лица (в базе нет таких полей). Дата нарушения, место
и пункты ГОСТ зависят от формулировок «проведённых с … по …», «выразившиеся» и «в нарушение п. …»:
если их нет, поля остаются пустыми.
Для протоколов в отношении **должностного лица** правила не проверялись на образцах: тип лица
определяется по заголовку, но остальные поля могут остаться пустыми или потребовать правки.
Правила написаны по одному образцу и будут уточняться по мере появления других форм.

Тестовый образец `tests/data/protocol_legal_entity.txt` обезличен: структура и формулировки
сохранены, имена, номера, ИНН/ОГРН и адреса заменены условными.

Ограничения извлечения текста:

* Текст OCR может содержать ошибки; при OCR программа предупреждает об этом в итоговом
  сообщении, реквизиты нужно проверять по оригиналу. Скорость OCR зависит от процессора
  (на старых машинах — десятки секунд на страницу).
* DOCX и ODT: колонтитулы, текстовые надписи и сноски пока не извлекаются.
* Форматы, кроме PDF, DOCX, ODT и DOC, не поддерживаются (сообщение об этом показывается).
* Защищённые паролем PDF не обрабатываются.

## Требования

* Python 3.9 или новее (с модулем `venv`);
* SQLite 3.24+ (для полнотекстового поиска нужна сборка с FTS5 — в Python из Ubuntu она есть;
  без FTS5 поиск по тексту работает медленнее, по подстрокам);
* pip-пакеты (ставятся в виртуальное окружение): PySide6, PyMuPDF, python-docx, odfpy, pytest;
* системные программы (нужны для обработки сканов и DOC): Tesseract с языком `rus`, LibreOffice (`soffice`).

## Установка без изменения системного Python

Все pip-пакеты ставятся только в папку проекта `.venv`. Системные пакеты (`apt`) нужны
только для Tesseract, LibreOffice и библиотек Qt, а системный Python не меняется.

### Ubuntu (22.04 / 24.04)

```bash
# 1. Системные пакеты (нужны права администратора)
sudo apt update
sudo apt install -y python3 python3-venv python3-pip \
    libegl1 libgl1 libxkbcommon-x11-0 libxcb-cursor0 libdbus-1-3 \
    tesseract-ocr tesseract-ocr-rus libreoffice-writer

# 2. Виртуальное окружение и зависимости (без sudo)
cd protocol-archive
scripts/install.sh
```

### ALT Linux

Точные имена пакетов в ALT зависят от ветки (p10, p11, Sisyphus), в этой работе они на ALT
**не проверялись**. Сначала найдите их:

```bash
apt-cache search tesseract | grep -i -E 'tesseract|rus'
apt-cache search libreoffice | head
python3 --version
python3 -c "import venv, ensurepip" && echo "venv доступен"
```

Затем установите найденные пакеты (пример; подставьте реальные имена из вывода выше):

```bash
su -
apt-get update
apt-get install tesseract tesseract-langpack-rus LibreOffice   # имена проверьте через apt-cache
exit
```

Установка проекта такая же, как в Ubuntu:

```bash
cd protocol-archive
scripts/install.sh
```

Если pip не может установить PySide6 (нет колёс под вашу версию Python или glibc), поставьте
`PySide6` из репозитория ALT (поищите `apt-cache search pyside6`) и запустите установку так,
чтобы окружение видело системные пакеты — системный Python при этом не меняется:

```bash
scripts/install.sh --system-site-packages
```

### Старые процессоры (без SSE4.2 / POPCNT, например Core 2 Duo)

Колёса PySide6 с PyPI на таких процессорах аварийно завершаются при запуске
(`Incompatible processor. This Qt build requires the following features: sse4.2 popcnt`).
Используйте Qt из репозитория дистрибутива:

```bash
apt-cache search -i pyside6                      # найдите пакет PySide6 для Python 3
su -
apt-get install <найденный пакет PySide6>
exit
rm -rf .venv
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -e . --no-deps
.venv/bin/pip install "PyMuPDF>=1.23,<2" python-docx odfpy pytest
.venv/bin/python -c "from PySide6.QtWidgets import QApplication; print('Qt работает')"
```

PyMuPDF закреплён на версии 1.x: версия 2.0 тянет `onnxruntime` и `numpy` (модули машинного
обучения), которые проекту не нужны.

### Установка вручную (то же, что делает `scripts/install.sh`)

```bash
cd protocol-archive
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e ".[dev]"
```

## Проверка зависимостей

```bash
.venv/bin/python -m protocol_archive --check
```

Выводит `OK` / `WARN` / `FAIL` для каждой зависимости и подсказку, что установить. Код
возврата 1 только при отсутствии обязательного (Python, SQLite, PySide6).
Нехватка PyMuPDF, python-docx, odfpy, Tesseract / `rus` или LibreOffice даёт `WARN`: программа запускается, но соответствующие форматы обрабатываться не будут. Ту же проверку можно
открыть в программе: «Справка → Проверка зависимостей…».

## Запуск

```bash
.venv/bin/protocol-archive
# или
.venv/bin/python -m protocol_archive
# с указанием файла базы
.venv/bin/protocol-archive --db ~/archive/protocols.sqlite3
```

База по умолчанию: `~/.local/share/protocol-archive/archive.sqlite3`
(учитывается `XDG_DATA_HOME`). Переменные окружения: `PROTOCOL_ARCHIVE_DB` — путь к базе,
`PROTOCOL_ARCHIVE_BACKUPS` — папка резервных копий.

Запуск без графической сессии (например, по SSH) для проверки:
`QT_QPA_PLATFORM=offscreen .venv/bin/protocol-archive`.

## Тесты

```bash
.venv/bin/python -m pytest
```

Тесты окна выполняются в режиме `offscreen` и не требуют экрана. Если PySide6 не
установлен, тесты окна пропускаются (это видно в итоговой строке pytest).

## Резервные копии

«Файл → Создать резервную копию базы» (Ctrl+B). Копия создаётся средствами SQLite
(безопасно при открытой базе), проверяется `PRAGMA integrity_check` и сохраняется как
`archive_ГГГГММДД_ЧЧММСС.sqlite3` в папке `backups` рядом с базой; хранятся 10 последних.
Копируется только база — не оригиналы документов.

Восстановление вручную: закройте программу и замените файл базы нужной копией
(удалите также файлы `*.sqlite3-wal` и `*.sqlite3-shm` рядом с базой).

## Модель данных

Версия схемы — 4 (таблица `protocol_evidence` — откуда взяты автоматически извлечённые значения; колонка `protocols.gost_norms` — нарушенные пункты ГОСТ). База версии 1 (с полем госномера) при открытии автоматически
мигрируется: поле `vehicle_plate` удаляется вместе со значениями, тип лица остаётся пустым
(программа не угадывает его). Перед обновлением рекомендуется сделать резервную копию (Ctrl+B).

* `documents` — путь к оригиналу (уникален), имя, тип, размер, время изменения, SHA-256,
  статус (`new`, `processed`, `error`, `missing`).
* `protocols` — реквизиты протокола, связь с документом; даты хранятся как `ГГГГ-ММ-ДД`,
  в интерфейсе показываются как `ДД.ММ.ГГГГ`. Протоколы ведутся только в отношении
  должностных и юридических лиц: поле `offender_type` принимает `official` (должностное
  лицо), `legal_entity` (юридическое лицо) или пусто (не указан), а `offender_name` — это
  ФИО должностного лица или наименование юрлица. Статус записи: `manual`, `extracted`,
  `verified`.
* `document_texts` + `document_texts_fts` — извлечённый текст (источник: `pdf-text`, `ocr`,
  `pdf-text+ocr`, `docx`, `odt`, `doc`) и полнотекстовый индекс.

Если файл-оригинал изменился (другой хэш), при повторном добавлении документ получает
статус `new`, так как ранее извлечённые сведения могли устареть.
